# 远程管理面（ISC Mizar）

> 本文是远程访问这条链路的实现说明。设计依据见
> [`DECISIONS.md`](./DECISIONS.md) 的 [D38](./DECISIONS.md#d38-远程管理面isc-mizar的安全模型)
> 与 [D09](./DECISIONS.md#d09-管理接口安全边界)。

## 1. 它解决的问题

内核的本地管理面只监听命名管道 / Unix socket / 回环（D09），而手机在
另一个进程、另一台设备上。远程访问把**同一批处理器**在局域网上暴露一份，
但只暴露其中经过挑选的一部分。

## 2. 两条链，互不影响

```
本地管理面（不变）                     远程管理面（新增）
─────────────────────              ─────────────────────
UDS / 命名管道 / 127.0.0.1:0        0.0.0.0:8788（默认，可改）
LoopbackGuard（Host 白名单）        无（Host 按定义不是本机）
单一本地 token（每次启动重生）       每设备一个长期令牌（只存哈希）
全部 82 条路由 + 控制台              33 条白名单路由（默认拒绝）
```

两者**不共享**中间件、监听器或令牌。本地 token 永远不出本机。

## 3. 信任模型

| 环节 | 机制 |
|---|---|
| 传输加密 | 自签 ECDSA P-256 证书，TLS 1.2+ |
| 服务端身份 | 客户端固定 **公钥（SPKI SHA-256）**，不是证书 |
| 首次信任 | 二维码携带指纹（强校验）；手输六位码时**必须**由用户比对两端指纹 |
| 设备身份 | 配对后签发的 256 位随机令牌，服务端只存 SHA-256 |
| 权限 | 两级角色，**服务端**判定 |
| 吊销 | 按设备吊销，级联到派生子设备，立即生效 |

### 为什么固定公钥而不是证书

地址一变（换网段、加网卡、路由器换 DHCP 段）就要重签证书。若固定整张
证书，重签后指纹变化，所有已配对的手机会报"服务器身份已变化"——而服务器
根本没换。重签时沿用同一把私钥，指纹因此稳定；只有换了机器（换了密钥）
它才变。

## 4. 配对流程

```
Phecda / CLI                     内核                        手机
     │  POST /v1/remote/pairing    │                           │
     ├────────────────────────────►│  会话（5 分钟、一次性）      │
     │  {qr_payload, manual_code}  │                           │
     │◄────────────────────────────┤                           │
     │  渲染二维码 / 显示六位码       │                           │
     │                             │       扫码或手输          │
     │                             │◄──────────────────────────┤
     │                             │  POST /v1/remote/pair     │
     │                             │  {secret|code, device}    │
     │                             ├──────────────────────────►│
     │                             │  {token, role, spki}      │
```

**二维码内容**（由内核生成，GUI 只渲染像素）：

```json
{
  "v": 1,
  "kind": "isc-remote",
  "name": "Mac-mini",
  "scheme": "https",
  "addresses": ["192.168.1.10:8788", "[240e:...]:8788", "Mac-mini.local:8788"],
  "spki": "<base64url SHA-256 of SubjectPublicKeyInfo>",
  "secret": "<base64url 32 bytes>",
  "exp": 1791118491
}
```

带多份候选地址是刻意的：换 WiFi、改网段、只走 IPv6 这几种情况都靠它
自愈，而多带几个地址的成本只有几十字节。

**六位手输码**用 Crockford base32（`0123456789ABCDEFGHJKMNPQRSTVWXYZ`）：
字母表去掉了 `I/L/O/U`，并且在解码时把 `I`/`L` 归一成 `1`、`O` 归一成 `0`。
"去掉易混字符"只解决了生成端，而真实失败发生在用户把屏幕上的字符念错、
再敲进另一个设备的时候。

## 5. 角色的确切边界

| 操作 | viewer | operator |
|---|:--:|:--:|
| 健康 / 版本 / 指标 / 建议 | ✅ | ✅ |
| 站点列表、详情、日志 | ✅ | ✅ |
| 凭据列表（字段已掩码）、区域、记录（读） | ✅ | ✅ |
| DDNS 任务列表（读） | ✅ | ✅ |
| 证书列表、反代状态 | ✅ | ✅ |
| 事件长轮询 | ✅ | ✅ |
| **DNS 记录增删改** | ❌ | ✅ |
| **DDNS 任务启停 / 立即执行** | ❌ | ✅ |
| **站点启停 / 重启** | ❌ | ✅ |
| **证书手动续期** | ❌ | ✅ |

**不在任何角色里**的（远程面根本不存在这些路径）：改设置、读审计、
写凭据、改动变更计划、导入导出配置、安装系统服务、改反代路由、
供给运行时、部署新站点。

## 6. 限流

| 对象 | 额度 |
|---|---|
| 配对路径（每源 IP） | 10 次/分，突发 5 |
| 单个会话 | 5 次失败即销毁 |
| 跨会话连续失败 | 10 次 → 锁 15 分钟 |
| 已鉴权设备 | 60 次/分，突发 30 |

配对是唯一免鉴权的路径，上面挂着 30 位的六位码。没有限流时，一个脚本
在五分钟的会话窗口里足够枚举掉相当一部分空间。

## 7. 推送（APNs）

- 推送由**内核**发出，不是手机自己轮询 —— 手机在后台被系统挂起时
  没有能力"定时醒来看看服务器怎么样"。
- 凭据（Team ID / Key ID / Bundle ID / `.p8`）用数据目录里已有的
  **主密钥加密**之后落在 `<root>/remote/apns.json`（0600），只写不读。
  走文件而不是数据库：凭据是一个整体，没有"列表/查询/过滤"的需求。
- 鉴权用 Token-based（ES256 JWT），**签名是 raw R||S 而非 ASN.1 DER** ——
  用错时 Apple 回 `403 InvalidProviderToken`，而那个错误看起来像
  "team id / key id 填错了"。JWT 缓存 50 分钟：APNs 会因为频繁换 token
  而拒绝连接（`TooManyProviderTokenUpdates`），那是一个"偶尔漏几条通知"
  的故障。
- 触发源只有五类：站点启动失败、站点不健康、证书失败、解析更新失败、
  公网地址变化。**其余一律不推** —— 全推的后果不是"信息多"，而是用户
  关掉通知权限，而那之后真正重要的那条也一起没了。
- 每设备每事件 5 分钟去重；投递流水落在 `remote_push_deliveries`。
- `410 Unregistered` 与 `400 BadDeviceToken` 会**清掉**那个令牌：
  继续给一个失效的令牌发通知不会有任何效果，而设备端也不会知道。
- **前提**：APNs 需要付费 Apple Developer 账号。没有账号时整条链路
  无法真机验证，验收用假 APNs 服务端覆盖（见 §10）。
- **内核不在跑就不会有推送**。Phecda 关掉且内核没装成系统服务时，
  手机既连不上也收不到通知 —— 这一点写在界面上，而不是让用户自己发现。

## 8. 数据与文件

| 位置 | 内容 | 权限 |
|---|---|---|
| `<root>/remote/tls.key` | 自签证书私钥 | 0600 |
| `<root>/remote/tls.crt` | 自签证书 | 0644 |
| `remote_devices` 表 | 设备、角色、令牌哈希、APNs 令牌 | 数据库 |
| `remote_push_deliveries` 表 | 推送投递流水 | 数据库 |
| 配对会话 | **只在内存里** | — |

配对会话不落库：它最多活五分钟，重启后继续持有它没有意义（用户手上的
二维码已经作废），而落库就多了一张需要清理的表。

## 9. 网络前提

- 手机与服务端需要在**同一可达网络**。支持 IPv4 私有地址、IPv6 全局
  单播地址与 `<hostname>.local`（mDNS）。
- **不做 NAT 穿透、不做中继**。移动网络下访问家庭内网需要用户自有
  IPv6 或一条 VPN。
- **不自动改防火墙**。端口被系统防火墙挡住时，Phecda 界面显示端口与
  自检信息；改防火墙属于 `change` 计划/回滚的范畴，不在本功能里。
- macOS 上 `getfsstat` 对同一 APFS 容器的每个卷报相同的块计数，因此
  远程指标只报 `/` 一个（其余 `/System/Volumes/*` 已过滤）—— 否则手机上
  会看到十几个数字完全一样、都快满了的"磁盘"。

## 10. 验收

```bash
# 不需要 root，40 项检查，含真实 TLS 握手与指纹比对
CGO_ENABLED=0 go build -o /tmp/isc-acc/isc ./cmd/isc
scripts/acceptance-remote.sh
```

`acceptance-remote.sh` 覆盖 48 项，其中包含整条推送链路：生成一份真的
`.p8` → 保存凭据 → 登记设备令牌 → 触发测试推送 → 断言假 APNs 收到的
请求形状（路径 / `apns-topic` / `apns-push-type` / `apns-priority` /
`Authorization` / 载荷）。

单元与集成测试：

| 文件 | 覆盖 |
|---|---|
| `internal/remote/remote_test.go` | 证书与指纹稳定性、角色序、令牌哈希、配对会话与锁定、限流 |
| `internal/remote/apns_test.go` | JWT 形状（含 raw R\|\|S 与缓存）、请求头、410/429/400 的处理、凭据存储与打码 |
| `internal/remote/push_test.go` | 事件→通知的白名单与翻译、去重、失效令牌清理、总开关、端到端投递 |
| `internal/api/remote_test.go` | 路由白名单矩阵（放行 + 拒绝 + viewer/operator + 未鉴权 + 吊销） |
| `internal/api/remote_tls_test.go` | 真实 TLS 监听、指纹固定、控制台引导端点不可达、状态端口一致 |

## 11. 已知取舍

- **Windows 上的远程面可用但未做专门验收**（TLS 与监听是纯标准库代码）。
- **令牌长期有效**（D38 的理由）。用户丢手机的正确处置是在 Phecda 里吊销。
- **APNs 的投递只在假服务端上验证过**：真机推送需要付费开发者账号与
  一台真手机，而本机两样都没有。请求的形状、重试、410 的处理、凭据的
  存取全部有测试覆盖；未覆盖的是 Apple 那一侧的实际接受度。
